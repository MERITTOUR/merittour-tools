## 1. 관리자가 할 일 (한 번)

메뉴 이름은 ChatGPT 버전에 따라 조금 다를 수 있습니다. 순서대로 하면 됩니다.

1. **워크스페이스 만들기** — 이름 「메리트투어」. 관리자(Owner)는 2명(대표 + 1명)으로 두고, 나머지는 멤버로 초대합니다. 초대는 회사 메일(@merittour.co.kr)로.
2. **보안 설정**
   - 2단계 인증(2FA)을 전원 켜게 합니다(워크스페이스 설정에서 필수로 둘 수 있으면 필수로).
   - GPT 공유 범위는 **워크스페이스 안**으로만. 「누구나 링크로」 공개는 끕니다.
   - 대화·파일이 **모델 학습에 쓰이지 않는 설정**인지 확인합니다(업무용 워크스페이스는 기본으로 제외되지만 설정 화면에서 한 번 확인).
   - 개인 메모리(기억) 기능은 **끄기를 권장**합니다 — 손님 이름·연락처가 기억에 남지 않게. 워크스페이스에서 일괄로 끌 수 있으면 끕니다.
   - 커넥터(Google Drive 등)는 관리자가 허용한 것만. 통합 자료실을 붙일 때는 계약서·정산·회원 자료 폴더는 **제외**합니다.
3. **공통 맞춤 설정 배포** — `custom_instructions.md` 의 두 칸을 직원에게 보내 각자 「맞춤 설정」에 붙여 넣게 합니다(워크스페이스가 공통 지침을 지원하면 관리자가 한 번에 넣습니다).
4. **GPT 4개 만들기** — 「GPT 만들기 → 구성」에서 `gpts/` 의 파일을 지침 칸에 그대로 붙여 넣고, 아래 표대로 지식 파일을 올리고, 공유 범위를 「워크스페이스」로 둡니다.

   | GPT 이름 | 지침 파일 | 지식 파일 | 웹 검색 |
   |---|---|---|---|
   | 메리트투어 손님 안내문 | `gpts/01_guest_notice.md` | style_guide · faq_2027 · guide_2027.txt | 끔 |
   | 메리트투어 일본 현지 연락 | `gpts/02_japan_contact.md` | style_guide | 켜도 됨 |
   | 메리트투어 업무 문서 정리 | `gpts/03_work_docs.md` | style_guide | 끔 |
   | 메리트투어 문의·민원 응대 | `gpts/04_inquiry_reply.md` | style_guide · faq_2027 · guide_2027.txt | 끔 |

   - 「대화 시작 문구」는 각 지침 파일 끝의 4개를 넣습니다.
   - 웹 검색을 끄는 이유: 손님 안내는 우리 자료만 근거로 써야 합니다. 검색이 켜져 있으면 다른 여행사 글이나 옛 요금을 섞어 씁니다.
5. **온보딩 공지** — `onboarding_message.md` 를 직원 단체방에 보냅니다.

## 2. 전 직원 사용 규칙 (지키지 않으면 쓰지 않는 것이 낫습니다)

1. **넣지 않는 것** — 회원·손님의 실명+연락처+생년월일 조합, 주민번호, 여권번호, 계좌·카드번호, 엠클릭 화면 캡처 원본(회원 명단이 보임), 계약서 전문, 직원 개인정보, 입금 계좌. 꼭 필요하면 **가상 값으로 바꿔서**(홍길동 · 010-1234-5678 · 예약번호 30001234) 넣습니다.
2. **숫자는 믿지 않는다** — 요금·날짜·조건·환율은 2027 안내문(https://merittour.github.io/2027/)과 사내 「리조트 정보」가 기준입니다. ChatGPT 가 만든 숫자는 반드시 원본과 대조합니다. 지식 파일에 없는 숫자를 물으면 「확인 필요」로 나오게 지침을 두었습니다.
3. **손님께 보내기 전 검토** — 표기 규칙(`knowledge/style_guide.md`)대로인지, 날짜·요일·금액이 맞는지, 인사말이 겹치지 않는지 사람이 봅니다. 단체 발송은 담당자 1명이 더 봅니다.
4. **파일 업로드** — 공개 안내문·표기 규칙·FAQ 같은 공개 자료만. 사내 수치(블록 수·회원 수·정산)는 올리지 않습니다.
5. **개인 계정과 섞지 않는다** — 업무는 워크스페이스 계정에서만. 개인 계정(학습에 쓰일 수 있음)에 회사 자료를 넣지 않습니다.
6. **결과의 책임은 보낸 사람** — ChatGPT 가 썼다는 것은 이유가 되지 않습니다.

## 3. 어떤 일에 어느 GPT 를 쓰나

| 일 | GPT | 비고 |
|---|---|---|
| 단체 문자 · 카카오톡 공지 · 안내문 문장 다듬기 | 손님 안내문 | 양식·표기·길이까지 맞춰 줌 |
| 손님 질문에 답하기 · 환율·환불·요금 설명 · 불만 응대 | 문의·민원 응대 | 기준은 FAQ·안내문, 예외는 약속하지 않음 |
| 리조트·SaiZen 에 보내는 일본어 메일 · 받은 일본어 메일 번역·요약 | 일본 현지 연락 | 일본어 본문 + 한국어 요약을 같이 줌 |
| 엠클릭 등 시스템 요청서 · 회의록 정리 · 붙여 넣은 표 정리 | 업무 문서 정리 | 번호·그림 참조·독립 항목 틀 |
| 영문 입국 안내 · 영문 주소 표기 | 손님 안내문 | 도구함 「일본 입국 안내 문안」이 먼저 — 그 밖의 영문만 |

도구함(`sales/`)에 이미 있는 것(일본 입국 안내 문안 · 리조트 날씨 안내문 · 닐라이 견적·확정서)은 도구함을 씁니다. ChatGPT 는 그 밖의 글을 쓰는 데 씁니다.

## 4. 지식 파일 만드는 법 · 갱신

- `knowledge/style_guide.md` · `knowledge/faq_2027.md` 는 이 저장소에서 내려받아 그대로 올립니다.
- `guide_2027.txt` 는 안내문 페이지(https://merittour.github.io/2027/)를 열어 **전체 선택(Ctrl+A) → 복사 → 메모장에 붙여 넣어 저장**한 텍스트 파일입니다. 안내문이 바뀔 때마다(띠가 뜨는 변경) 다시 만들어 GPT 두 개의 지식 파일을 교체합니다. 예약 방법 페이지(https://merittour.github.io/2027/booking/)도 같은 방법으로 `booking_2027.txt` 를 만들어 올리면 로그인·예약 절차 질문에 답합니다.
- 표기 규칙이 바뀌면(이름 변경 · 금지 표현 추가) `style_guide.md` 를 고치고 GPT 네 개 모두 교체합니다 — **한 GPT 만 바꾸지 않습니다.**

## 5. 운영

- 관리자 1명이 월 1회: 멤버 목록(퇴사자 제거) · GPT 지식 파일 날짜 · 공유 범위 · 2FA 를 확인합니다.
- 직원이 좋은 프롬프트를 찾으면 `prompts.md` 에 보태고, GPT 가 틀린 답을 하면 FAQ 나 지침에 그 사례를 한 줄 더합니다(사례를 적을 때 손님 실명은 적지 않습니다).
- 이 문서의 기준(표기 규칙·숫자)은 merittour.github.io 의 CLAUDE.md 와 2027 안내문이 원본입니다. 그쪽이 바뀌면 여기를 따라 고칩니다.
