# 통합 업무 허브 (dashboard) — 기술 명세

`tools/dashboard/index.html`의 현재 구조와 동작을 정리한 문서. 이어서 작업할 때 이 문서를 참조하면 전체 맥락을 빠르게 파악할 수 있다.

## 개요
엠클릭 2종(예약리스트·일행별예약)을 행사번호(eventSeq)로 묶어 예약 흐름대로 정리하고, 추가로 엠클릭 「호텔별 예약현황」 표를 붙여넣어 호텔 블록 재고까지 즉석 분석하는 단일 HTML 도구. 사이젠 같은 현장 배정표가 아니라, 정보를 모아 점검하고 단체 발송·개별 연락 대상을 뽑는 조회·집계·검증 도구다. 엠클릭이 본체 ERP이고 이 도구는 그 데이터를 모아 더 편하게 만드는 보조 허브다. 제목은 "통합 업무 허브".

## 입력
### 통합 분석용 (2종 통합 완료, eventSeq 결합, 각각 다중 파일 병합 지원)
| 파일 | 필수 여부 | 엠클릭 다운로드 위치 | 용도 |
|---|---|---|---|
| 예약리스트 | 필수 | 출발일별 / 예약일별 → 예약현황 탭 | 구분·호텔·명단·미수금·판매금액·비고 3종(비고·현지 비고·기타 비고) |
| 일행별예약 | 필수 | 출발일별 / 예약일별 → 탑승자정보 탭 | 개인(탑승객) 명단 + 항공시각 4종·PNR·항공사·사전좌석·여권 |

- 두 파일 모두 엠클릭 출발일별/예약일별 화면에서 받으며, 한 번에 500행씩 다운로드 → 분할분을 같은 칸에 여러 개 올리면 자동 병합
- 예약리스트·일행별예약이 모두 올라오면 [통합 분석 실행] 활성화
- 업로드 화면 카드에 위 다운로드 위치·500행 분할 안내를 명시(담당자 혼동 방지)

#### 업로드 2종 통합 (완료, 2026-06)
엠클릭 컬럼 변경으로 **예약리스트 + 일행별예약 2종**만으로 모든 섹션이 동작한다. 일행별예약 한 파일에 다음이 모두 포함된다: **PNR · 항공사 · 출발편 · 귀국편 · 한국출발 · 현지도착 · 현지출발 · 한국도착 · 출발지 · 도착지 · 사전좌석 · 여권번호 · 만료일 · 발행국가**. 구 APIS·현지도착 파일은 **폐지**됐고, 코드 내부의 `apisMap`(항공·PNR·여권 집계)과 `arrivalMap`(항공시각)은 모두 **일행별예약 단일 소스에서 파생**된다(외부 업로드 없음).
- 항공시각 4종 매핑: `한국출발`(출국 한국 출발시각) → `현지도착`(출국 현지 도착시각, 출국 송영) / `현지출발`(귀국 현지 출발시각, 귀국 송영) → `한국도착`(귀국 한국 도착시각). 송영 출국행 날짜=`출발일자`(arrDateLocal), 귀국행 날짜=`도착일자`(depDateLocal).
- 현지수배(항공편 없음) 인원은 `arrivalMap` 미생성 + ⑧정산에서 「지상만」 자동 처리.
- PNR 콤마(전각 `，` 포함) 분리 전부 수집, trailing 공백 trim.
- 데이터 검수의 **APIS↔일행별 영문명 교차검증은 폐지**(단일 소스로 대조 대상 없음). 영문명 공백·여권 만료·여권/PNR 누락 검사는 일행별예약 기준으로 유지.


### ② 호텔 블록용 (별도, 붙여넣기)
- 엠클릭 「호텔별 예약현황」 표를 드래그 복사 → 붙여넣기(Ctrl+V)
- 파일 업로드·저장 없이 휘발성 즉석 분석(직전 입력만 localStorage 임시 보관)
- 통합 분석과 독립 동작(② 탭은 붙여넣기만으로 열림)

## 섹션 — 실제 내비게이션 순서 (코드 기준)

내비게이션 실제 순서·번호는 다음과 같다(`tools/dashboard/index.html`의 `<div class="nav">`):

```
업로드 → ① 리조트 마스터 → ② 호텔 블록 → ③ 데이터 검수 → ④ 요금 관리
→ ⑤ 예약 관리 → ⑥ 항공 정보 ┊ (준비중) 확정서 생성 · 정산 · 보험 · 송영 · 숙소 · 골프 · 식사
─ 구분선 ─
(준비중) 보험 정보 · 송영 정보 · 숙소 정보 · 골프 정보 · 식사 정보
```

활성 6개(①~⑥: 리조트·호텔블록·검수·요금관리·예약·항공)에는 원형 번호가 붙고, 준비중 7개(확정서·정산·보험·송영·숙소·골프·식사)는 번호 없이 `nav-soon` 「준비중」 배지가 달린다. **다만 준비중 7개도 렌더 함수가 모두 구현돼 있고, `analyze()` 완료 시 unlock 배열 `['booking','insurance','air','transfer','accom','golf','dinner','verify','audit','doc','settle']`에 포함되어 잠금이 풀린다.** 즉 통합 분석을 실행하면 준비중 섹션도 클릭·동작한다(보험과 동일). 확정서 생성·정산은 기능 완성도가 높지만 표·정렬 등 UI 마감과 배포 시점 정책상 「준비중」으로 분류했다 — 배지는 "정식 노출 보류" 표시일 뿐 기능은 살아 있는 과도기 상태다. 아래 본문은 기능 단위로 설명하며, 각 항목 끝에 실제 nav 위치를 표기한다.

0. **업로드** (nav: 업로드) — 예약리스트·일행별예약 2종 필수, eventSeq 통합 엔진. 같은 종류 다중 파일 자동 병합. (구 현지도착·APIS는 일행별예약에 흡수돼 폐지)
1. **리조트 마스터** (nav: ①) — 실제 판매 상품 18개 숙소를 아코디언(접힘) 카드로. 각 숙소별 단가(체재·송영·그린피·식사) + **현지정산단가(`localRate`, ¥/인박 — 일본 측 청구 단가. 비우면 체재비 − ¥1,000 자동(`rmLocalRate`), 명시적 0 허용. 체재비와의 차액 × 박수가 ⑧ 정산의 체재마진)** + **회원관리비(원, 숙소별 입력)** + 출발 일정·출발 공항·도착 공항 + **요금 도착코드(`arrCode`, IATA)**. 카드 머리에 정원(보유 합산 자동)·출발일정 배지. 공통 마스터(월별 환율 테이블·항공요금 테이블[안내 요금 + **발권원가(`cost`)** — 같은 조건 행에 나란히 입력, 항공수익/인 = 차액 자동 표시. 입력 칸은 「안내 요금 · 고객」(블루) / 「발권원가 · 내부」(보라 라벨·배경)로 시각 구분하고 테이블의 발권원가 열도 보라 톤(.af-cost-cell). 마스터 내보내기/불러오기에 포함되어 직원 공유]·**변경 이력**). 회원관리비는 숙소별 값이 단일 출처이며 기본 50,000원/인, 받지 않는 숙소만 0으로 비움(과거 공통 마스터의 단일 회원관리비 칸은 제거, 1회성 마이그레이션 `mt_notify_mgmtMigrated`로 기존 저장본 0→50,000 보정). 환율은 단일 「적용 환율」 없이 월별 환율 테이블만 사용(출발일자별 안내 방식). **요금 도착코드**는 지역명(`airIn`, 안내 표시용 한글)과 별개로 항공요금 매칭에 쓰는 공항 IATA 코드(벳푸→FUK, 이바라키→NRT, 나가노→KIJ, 구마모토→KMJ, 나고야→NGO, 미야자키→KMI, 쿠알라룸푸르→KUL). 지역명과 실제 이용 공항이 다른 상품(벳푸=후쿠오카, 이바라키=나리타, 나가노=니가타)을 정확히 매칭하기 위함. **변경 이력**은 마스터·환율·항공요금·관리비 등 값 변경을 대상·항목·전→후로 기록(최근 100건 링버퍼, 라이트 톤 접이식 표, 이력 비우기 버튼). localStorage 자동 저장. **마스터 내보내기/불러오기**: 공통 마스터(리조트+환율+항공요금+변경이력)를 JSON 파일로 주고받아 직원 간 같은 기준값 공유(`exportMaster`/`importMaster`). 한 명이 관리·내보내고 나머지가 불러오는 방식(서버·키 불필요). 불러오기는 기본값 병합·형식 검증·확인 후 적용하며 변경이력에 「마스터 일괄 불러오기」 기록. 팀 지정·발권 체크·요금 보정 등 개인 작업값은 제외. **판매중지 토글**: 숙소별 판매중/판매중지 전환(`sellStop`, `toggleSellStop`). 판매중지 숙소는 블록 현황·출발 일정 조회·예약 가능 일정 공지·패키지 프리셋 드롭다운에서 기본 제외(블록 현황은 「판매중지 숙소 포함」 체크로 회색 표시 가능). 데이터는 보존되어 「판매재개」로 즉시 복귀. 변경이력 기록·내보내기 포함. **입력 완성도 표시**(배포 지원): 숙소 카드 헤더에 단가·도착공항·항공요금 입력 여부 배지(`rmCompleteBadge` — ✓입력완료 / ▲N/3·미입력항목), 마스터 상단에 전체 진행률 바·미완 숙소 목록(`renderRmCompletenessSummary`). 항공요금 입력 시 즉시 갱신. **배포 안내 박스**: 마스터는 브라우저(PC) localStorage에만 저장되므로, 관리자가 입력 완료 후 「마스터 내보내기」로 JSON 배포 → 직원은 「마스터 불러오기」 1회 후 각자 엠클릭 파일만 업로드하는 흐름을 상단에 안내.
2. **호텔 블록** — 엠클릭 표 붙여넣기 기반. 6개 서브탭(아래). 리조트 마스터에서 재고·별칭·임의배정·출발일정을 파생하므로 데이터 업로드 전에도 독립 동작.
3. **데이터 검수** — 엠클릭 수기 입력 오류를 발권 전에 검출(자동 수정 없음, 담당자가 엠클릭에서 직접 수정). 일행별예약 업로드 시 동작. **아코디언 UI**: 항목별 접이식 카드로, 헤더에 건수·심각도 점(🔴 있으면 빨강)을 표시해 접힌 상태에서도 한눈에 파악. **한 번에 하나만 펼침**(`auditOpen`, `auditToggle` — 다른 항목 열면 이전 항목 자동 닫힘), 0건 항목은 흐리게 "정상" 표시·클릭 불가. 검출 항목: ① 영문성·영문이름 공백·특수문자(영문이름 공백은 발권·온라인 체크인 안내와 어긋나는 핵심 건이라 긴급), ② **영문명 재확인**(`auditEngName` — 한글명 대비 영문 표기 점검: 🔴 한국인 영문 미입력·영문칸 한글/숫자/특수문자 섞임·성씨 초성 자음 불일치[`SURNAME_INITIAL`, 김→K/G인데 P 등], 🟠 성씨 표준표기[`SURNAME_ROMAN`] 변형·외국인 추정. 로마자 표기 다양성 고려해 초성 자음이 맞으면 정상 처리 — YOO/YOU/RYU 등 변형 통과, 오탐 최소화), ③ 여권 만료 임박(출발일 기준 6개월 미만 주황·3개월 미만 빨강), ④ 만료일·⑤ 여권번호·⑥ PNR 누락. (구 APIS↔일행별예약 영문명 교차검증은 2종 통합으로 단일 소스가 되어 폐지) 심각도 요약(긴급/확인필요)과 필터(전체/긴급/확인필요), 현재값·권장값 병기. 화면 표시 전용(엑셀 내보내기 없음).
4. **요금 관리** (구 「요금 검증」) — **요금 달력(정방향 산출)이 기본 뷰**, 표 보기(역방향 검증)가 두 번째(`verifyView='calendar'` 기본, 뷰 토글 「📅 요금 달력 / 📋 표 보기」 순). 요금 달력은 리조트·출발지 선택 → 출발 패턴 달력 → 날짜별 안내 투어피 명세(마스터 단가 + 그 달 환율 + 항공요금 정방향). 표 보기는 리조트 마스터 단가 × 월별 환율 + 항공요금으로 예상 판매금액 산출 → 실제와 대조. 회원관리비는 숙소별 값(`u.mgmt`)을 사용. 환율은 `rateForMonth(dep)`가 출국월(YYYY-MM) 월별 환율만 조회하며, 미등록 월은 0 → "기준 미등록"으로 검증에서 제외(단일 적용 환율 폴백 없음). 월별 환율 기준: 출국 2달 전 월 1일자 하나은행 현찰 살 때 최초 고시 환율. **항공요금 매칭**은 저장값·팀값을 모두 IATA 코드로 정규화해 비교(`airportCode`)하므로 입력 표기 차이(인천/ICN, 구마모토/KMJ)를 흡수. 도착지는 **① 숙소 마스터 도착코드(`arrCode`) → ② APIS 도착지** 순으로 결정. **패키지가(1인)**: 벳푸 박수별·나가노 기간별처럼 항공까지 합쳐 단일가로 안내하는 상품용. 팀별 검증 행의 `패키지가(1인)` 칸에 1인 원화 총액을 넣으면 분해식(체재비·송영비·항공·환율)을 우회하고 **패키지가 × 인원**을 예상 판매금액으로 사용(`vAdjust[seq].pkgPrice`). 패키지 적용 팀은 숙소 옆 「패키지」 배지, 분해 항목 셀 흐림 처리, 예상 판매금액 아래 패키지 단가×인원 근거 표기. 박수·시즌 변형을 마스터 표 없이 팀 단위로 흡수. **패키지가 프리셋**: 동일한 패키지가는 리조트 마스터 「패키지가 프리셋」(숙소+박수→1인가)에 등록하면, 검증에서 팀 패키지가 미입력 시 숙소·박수 매칭으로 자동 적용(`pkgPresetFor`, 「패키지·프리셋」 배지). 팀 직접 입력값이 우선. `commonMaster.pkgPresets`에 저장돼 내보내기/불러오기로 공유.

- `buildApisMap()` → eventSeq별 PNR 집합(콤마 전부)·항공사·편명·좌석 + 개인별 여권/좌석/PNR.
- `parseTeamName(remark)` → 비고에서 `팀:xxx` 추출.
- `calcExpected(t)` / `airfareFor(t)` / `rateForMonth(dep)` → 요금 검증. `rateForMonth`는 월별 환율만 조회(미등록 월 0 반환, 단일 환율 폴백 없음). `airfareFor`는 출발지·도착지를 `airportCode`로 정규화 비교, 도착지는 숙소 `arrCode` 우선. `calcExpected`는 `vAdjust[seq].pkgPrice`(1인 패키지가)가 있으면 분해식 대신 `pkgPrice×pax`를 예상 판매금액으로 반환(`isPkg` 플래그). `pkgPresetFor(accom,nights)`로 프리셋 조회(팀 입력 없을 때). `renderPkgPresets`/`addPkgPreset`/`delPkgPreset`로 마스터 프리셋 관리.
- `logChange(target,field,before,after)` / `renderChangeLog()` / `clearChangeLog()` → 리조트 마스터 변경 이력. `updateResort`·`updateCommon`·`addMonthlyRate`·`addAirfare` 등에서 값이 실제로 바뀐 경우만 1건 기록(전→후), 최근 100건 링버퍼.
- `exportMaster()` / `importMaster(input)` → 공통 마스터 JSON 내보내기/불러오기(직원 간 공유). 파일에 `_type:merittour-master`·`exportedAt`·resortMaster·commonMaster·changeLog 포함. 불러오기 시 `RESORT_DEFAULTS` 병합·형식 검증, 변경이력 병합(최근 100건).

- **동기화 패턴:** localStorage 즉시 렌더 → async Supabase fetch 후 재렌더. `version` 필드 기반 **낙관적 잠금**(동시 수정 덮어쓰기 방지). 변경 이력은 `resort_master_history`에 `updated_by`(아래 게이트)와 함께 기록.
- **비밀번호 게이트:** 공유 비밀번호 SHA-256(SubtleCrypto), sessionStorage로 게이트 통과 유지, localStorage로 이름 보존 → Supabase `updated_by`에 기록.
- **착수 시 첫 작업(필수):** `resort_master`/`resort_master_history` RLS 쓰기 정책이 현재 **always-true**(허용 과다) → public 저장소 anon 키로 누구나 덮어쓸 수 있어 **먼저 잠가야** 함. `about/` 공개 페이지용 anon **SELECT 전용** 정책도 별도 필요.
