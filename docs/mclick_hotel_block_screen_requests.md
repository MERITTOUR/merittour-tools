## 4. 회원 예약 화면 — 달력에 「전 일정 예약 가능」 기준 잔여 표시 (2026-10-16 추가)

Min(2026-10-16) 「회원이 보는 화면쪽에 캘린더 클릭하고 아래에 인원 추가할 때 모든 체류일 마감일자가 하루라도 없어야 예약이 되는건데 그전에 달력부터 안뜨게 하는 방법을 써야 함.
여행 패턴도 다 고르고 들어오는데 손님이 아주 열받음」 → 「지금은 이런 방식임. 클릭하고 아래를 또 봐야하니 불편함」(화면 캡처: 상품 상세 달력 → 요금구분 표 → 룸타입 ∨ 날짜별 내역).

**§1 과 다른 화면(회원 예약 홈페이지 www.merittour.co.kr 상품 상세)이라 문안을 따로 두었다 — 같이 보내되 메일 안에서 묶음을 나눈다.** 번호는 §1 에 이어 13~17.
캡처의 호텔명·잔여 숫자는 이 문서에 옮기지 않는다(공개 저장소 · 위 원칙과 같다).

   - 출발 요일이 아닌 날(지금도 선택 불가)과 구분되게 표시해 주시면 더 좋습니다.
15. 요금구분 표의 룸타입별 잔여도 같은 기준으로
   - 룸타입 잔여를 체류 전 일정의 최솟값으로 표시하고, 하루라도 마감이면 「마감」 + 인원 − + 비활성.

■ 가능하면 함께
16. 달력 칸에 룸타입별 표시(예: 트윈 · 싱글 각각) 또는 마우스를 올리면 룸타입별 잔여가 보이게.

- 손님 안내문 `/2027/booking/` 04 「예약 전에 꼭 확인하실 점」 확인 1(「체류하시는 날짜 모두에 객실이 남아 있어야 예약이 됩니다」 · 「안 되는 예」 카드 · `ROOMS_WARN` callout)이 바로 이 함정을 설명하는 자리다 — 13·14 가 반영되면 그 안내는 「달력의 숫자 = 그 출발일로 전 일정 예약 가능한 객실 수」로 바꾼다(없애지 말고 뜻을 바꾼다).

- 13 의 「룸타입 합계 또는 룸타입별」은 엠클릭이 고르게 두었다 — 합계만 보이면 16 이 뒤따라야 트윈/싱글 혼동이 안 생긴다.
- 사내 블록 화면(§1 의 5번 오버부킹 음수)과 같은 잔여 계산을 쓰므로, 손님 화면에서는 음수를 0(마감)으로 보여야 한다 — 13 에 「하루라도 마감이면 0」으로 적은 이유.
