# 엠클릭 요청 — 「호텔블록잔여현황」 화면 개선 (2026-10-15)

엠클릭 관리자 시스템 예약 > **호텔블록잔여현황**(출발년월 · 호텔명으로 조회 · 호텔 × 룸타입 × 블록 R/B × 1~31일 표)의 개선 요청 문안과 근거.
Min(2026-10-15) 「검색식에 호텔별 체크 검색 · 달력을 좌우로 이동하는 버튼 · 더 가능해 보이는 기능도 추천」 → 「오버부킹 날짜는 -2 이런 식으로 표기 희망」. 회신이 오면 이 문서 맨 아래 「회신」에 적는다.

**이 문서에는 블록·잔여 수량 같은 화면의 숫자를 옮겨 적지 않는다**(공개 저장소). 화면의 구성(조건 · 열 · 표시 방식)만 적는다.

## 1. 보낼 문안 (메일 · 카카오톡 공용 — 그대로 복사)

```
[메리트투어] 호텔블록잔여현황 화면 개선 요청

안녕하세요, 메리트투어입니다.
예약 > 호텔블록잔여현황 화면을 2027 시즌 회원 예약 기간에 자주 보게 되어, 아래 개선을 요청드립니다.
항목은 서로 독립적이니 가능한 것부터 부분 반영해 주셔도 됩니다.

■ 꼭 부탁드리는 것
1. 호텔 체크 선택 조회
   - 지금: 「호텔명」에 글자를 입력해 한 호텔씩 조회
   - 요청: 호텔 목록을 체크박스(여러 개 선택)로 두고, 체크한 호텔만 표에 나오게. 「전체 선택 / 해제」 버튼과 마지막 선택 기억(로그인 계정별)도 함께 부탁드립니다.
   - 가능하면 같은 자리에 룸타입(트윈 · 싱글 등) 체크도 두어 주세요.
2. 출발년월 좌우 이동 버튼
   - 지금: 달력 아이콘을 열어 연·월을 고른 뒤 조회
   - 요청: 출발년월 양옆에 「◀ 이전달」 「다음달 ▶」 버튼과 「이번 달」 버튼. 누르면 바로 조회되게(또는 조회 버튼은 그대로 두고 월만 바뀌게).
3. 두 달 이어 보기(또는 기간 조회)
   - 7박 일정은 월말 출발이면 다음 달까지 봐야 해서 지금은 두 번 조회해야 합니다(예: 4월 29일 출발 → 5월 6일 귀국).
   - 요청: 「출발년월 ~ 다음 달」을 한 표로 이어 보기, 또는 시작일~종료일 기간 조회.
4. 표 머리줄 · 왼쪽 열 고정(틀 고정)
   - 가로·세로로 스크롤하면 날짜 머리줄과 호텔명 · 룸타입 · 베드타입 · 블록 열이 사라져 어느 호텔의 어느 날인지 다시 올라가 봐야 합니다.
   - 요청: 날짜 머리줄은 위에, 호텔명~블록 열은 왼쪽에 고정.
5. 오버부킹 날짜는 음수로 표시
   - 지금: 블록보다 예약이 많아진 날도 잔여가 0 으로 보여 초과 여부와 초과 수량을 알 수 없습니다.
   - 요청: 잔여(R)를 「-2」처럼 음수로 표시(초과 수량). 음수 칸은 빨간 바탕 등으로 구분되고, 엑셀에도 같은 값이 나오게 부탁드립니다.

■ 가능하면 함께
6. 잔여 상태 표시 확대 — 지금은 잔여 0만 빨간 숫자. 잔여 1~2(기준값 설정 가능)는 노랑 등으로 구분하고, 「잔여 있는 날만 보기」 「마감만 보기」 필터.
7. 날짜 칸 클릭 → 그 호텔 · 룸타입 · 날짜의 예약 목록(출발일별 또는 예약일별)로 바로 이동.
8. 마지막 조회 조건 기억(출발년월 · 호텔 · 룸타입 선택) — 화면을 다시 열어도 같은 조건으로.
9. 조회 기준 시각 표시 + 새로고침 버튼(가능하면 자동 새로고침 간격 선택). 예약 기간에는 화면을 띄워 두고 봅니다.
10. 마우스를 올린 날짜 열 전체 강조(행·열 교차 강조).

■ 나중에라도 검토 부탁드리는 것
11. 일본 공휴일 날짜 표시(토·일과 같은 색 구분) — 공휴일에는 주말 요금 · 라운딩 운영 방식이 적용되어 블록을 볼 때 같이 봐야 합니다. 연도별 공휴일 등록 화면이 필요하면 저희가 날짜를 드리겠습니다.
12. 온라인(회원 예약 화면) 노출분과 전체 블록의 구분 표시 — 앞서 요청드린 룸타입 온라인 노출 on/off 와 짝으로, 손님 화면의 잔여와 관리자 화면의 잔여가 다를 때 확인용.

각 항목의 처리 가능 여부와 일정, 비용이 드는 항목이 있으면 함께 회신 부탁드립니다.
```

## 2. 왜 이렇게 묶었나 (전달할 때 참고)

|---|---|---|---|---|
| 1 | 호텔 체크 선택 조회 | 호텔명 글자 검색 · 한 호텔씩 | 담당 호텔 몇 곳만 한 표로 · 매번 이름 입력 없음 | 낮음 — 조회 조건 하나 추가(목록은 이미 있는 호텔 마스터) |
| 2 | 출발년월 ◀ ▶ 버튼 | 달력 아이콘 → 연·월 선택 → 조회(3번 누름) | 한 번 누름 · 우선예약 기간에 달 넘겨 보기 | 낮음 — 버튼 두 개 + 조회 호출 |
| 3 | 두 달 이어 보기 / 기간 조회 | 월 단위만 | 월말 출발 7박을 한 표에서 확인(손님 안내문 「안 되는 예」가 바로 이 경우 — 4/29 출발 · 5/2~5 마감) | 중간 — 표 열이 늘어남(가로 스크롤 전제) |

| 5 | 오버부킹 음수 표시 | 초과 예약도 잔여 0 으로 보임 | 어느 날 몇 실을 더 확보·조정해야 하는지 바로 보임 | 낮음 — 잔여 계산에서 0 으로 자르지 않으면 됨(화면·엑셀 같이) |

| 8 | 조회 조건 기억 | 열 때마다 초기화 | 반복 조회 시간 절약 | 낮음 |
| 9 | 기준 시각 · 새로고침 | 없음 | 예약 기간 중 최신 잔여 확인 | 낮음(자동 새로고침은 중간) |

| 11 | 일본 공휴일 표시 | 토·일만 색 | 요금·라운딩 기준일을 표에서 바로 봄 | 중간 — 공휴일 달력 등록 기능 필요 |

- 1·2·5 = Min 요청(5 = 2026-10-15 「오버부킹 날짜는 -2 이런 식으로 표기 희망」). 3·4 는 이 화면을 쓸 때 가장 자주 부딪히는 것이라 「꼭」에 같이 넣었다. 6~10 은 조회 화면의 흔한 편의 기능이라 반영 가능성이 높고, 11·12 는 다른 화면·데이터가 같이 바뀌어야 해서 뒤로 뺐다.
- 3번의 「4월 29일 출발 → 5월 6일 귀국」은 손님 페이지 `/2027/booking/` 04 「안 되는 예」 카드와 같은 예(간지호텔 트윈 · 달력 29일 2실 · 5/2~5 마감). 사내에서도 두 달을 따로 조회해야 보이는 경우라 함께 적었다.
- R/B 두 줄 = 잔여(R) · 블록(B). 사내 도구(`tools/dashboard` 블록 계산 · `mt_block_override` 웹오픈 수량 조정)가 보는 값과 같은 출처다 — 12번이 들어오면 사내 도구의 웹오픈 수량과 맞출 수 있다. 5번(음수 잔여)이 들어오면 사내 도구의 블록 계산도 초과분을 그대로 받을 수 있다(지금은 0 으로 잘린 값을 본다).
- 12번은 2026-09 에 보낸 「추가로 필요한 필드 4개」(룸타입 온라인 노출 on/off · 출발 가능 요일 · 온라인 판매 구분 · 예약 인원 하한·상한)와 같은 묶음이다 — CLAUDE.md 「엠클릭 현황」.
