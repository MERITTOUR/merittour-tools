# 여러 달 연결해서 보는 블록 현황

> 상태: **구현 완료** · 대상: `tools/dashboard/index.html` ② 호텔 블록

---

## 1. 먼저 — 지금 월말 출발편이 조용히 빠지고 있다

설계에 앞서 실측했다. 아소 야마나미 골프텔(목3박·일4박·수7박) 2026년 7월 기준:

| | |
|---|---|
| 그 달에 있어야 할 출발편 | 14개 |
| 화면에 나온 것 | 12개 |
| **누락** | **2개** — 7/29 수7박, 7/30 목3박 |

둘 다 숙박이 8월로 넘어가는 출발편이다. 원인은 연박 루프가 월 안에서만 돈다는 것.

```js
for(let k=0;k<p.nights;k++){
  const cd=d+k;
  if(cd>lastDay){ valid=false; break; }   // ← 달을 넘으면 그냥 버린다
  ...
}
if(valid && mn>=minRem) departs.push(...)
```

`valid=false`가 되면 그 출발편은 **목록에 아예 나타나지 않는다.** "잔여 부족"도 아니고 "확인 필요"도 아니고 그냥 없다. 팔 수 있는 일정을 못 팔고 있는데 화면상으로는 티가 안 난다.

**같은 코드가 예약 가능 공지 PNG(`noticeDepartList`)에도 있다.** 손님에게 나가는 안내에서 월말 출발편이 빠진다.

숙소 18개 × 매달이면 실제 손실은 위 2건보다 훨씬 크다. 박수가 길수록 심하다 — 7박이면 월말 7일치가 통째로 사라진다.

## 2. 지금 구조

| 것 | 형태 | 비고 |
|---|---|---|
| `blkParsed` | `{rows, days, month}` | **단일 월**. 화면 표의 원천 |
| `vcalBlocks` | `{'YYYY-MM': rows}` | 여러 달 누적. **휘발성**(새로고침 시 소멸) |
| 등록월 전환 네비 | `blkRenderMonthNav` | 등록한 달끼리 좌우 전환 — 여전히 **한 번에 한 달** |
| `vcalAvail` (요금달력) | — | **유일하게 월 경계를 넘어 계산**한다 |

즉 여러 달을 담을 그릇(`vcalBlocks`)과 월 경계를 넘는 계산 사례(`vcalAvail`)가 **이미 있다.** 나머지가 그걸 안 쓰고 있을 뿐이다.

---

## 3. 설계

### 핵심 — "월 안의 일자" 대신 "날짜"로 조회한다

지금 소비처들은 `used[dd]`(일자 2자리)로 조회한다. 이걸 날짜(YYYY-MM-DD) 기준으로 바꾸면 월 경계가 자연히 사라진다.

```js
// 그날 그 풀의 사용 객실 수. 그 달이 등록돼 있지 않으면 null(= 판단 보류)
function blkUsedOn(pool, ymd){
  const rows = vcalRowsForMonth(ymd.slice(0,7));
  if(!rows) return null;
  const dd = ymd.slice(8,10);
  let sum = 0;
  rows.forEach(r => { if(r.day===dd && blkPoolMatch(pool, r.hotel, r.room)) sum += r.used; });
  return sum;
}
```

`blkPoolCapOn(pool, ymd)`는 이미 날짜를 받는다. 짝이 맞는다.

### 단계 1 — 월 경계 출발편 살리기 (가장 급함)

연박 루프를 날짜로 돌린다.

```js
let cur = new Date(y, m-1, d), mn = Infinity, spill = '';
for(let k=0; k<p.nights; k++){
  const ymd = fmtYmd(cur);
  const used = blkUsedOn(pool, ymd);
  if(used === null){ spill = ymd.slice(0,7); break; }   // 그 달 미등록
  mn = Math.min(mn, blkPoolCapOn(pool, ymd) - used);
  cur.setDate(cur.getDate() + 1);
}
```

- 다음 달이 등록돼 있으면 **정상 계산**되어 목록에 뜬다
- 미등록이면 **조용히 빼지 말고** 「8월 미등록 — 확인 필요」 칩으로 보여준다

조용히 사라지는 것과 "확인 필요"로 보이는 것의 차이가 크다. 후자는 등록하면 되는 문제지만, 전자는 있는 줄도 모른다.

공지 PNG는 손님 발송물이므로 **미등록 구간을 안내에 넣지 않는다** — 대신 화면(직원용)에만 「8월 미등록」으로 표시해 등록을 유도한다.

### 단계 2 — 등록월을 저장한다

지금은 휘발성이라 새로고침하면 등록월이 날아간다. 그러면 단계 1이 매번 「미등록」으로 떨어진다. 단계 1을 쓸모 있게 하려면 이게 필요하다.

- 키 `mt_notify_blkMonths`, 형태는 `vcalBlocks` 그대로
- 한 달 rows가 보통 수백 건이라 3~4달치는 부담 없다
- 지난 달은 자동 정리(예: 3개월 지난 것 삭제) — 안 그러면 계속 쌓인다

### 단계 3 — 표를 이어서 보기

```
② 호텔 블록
  [출발년월 2026-07] [붙여넣기 영역]
  등록월   [7월] [8월]  [+ 이 달 등록]
  표시 기간  ○ 7월   ○ 8월   ● 7~8월 이어보기
```

- 「이어보기」면 표 열이 7/1~8/31 (62칸). 이미 가로 스크롤 표라 구조 변경은 없다
- **월이 바뀌는 지점에 굵은 구분선**과 열 머리에 `8/1`처럼 월을 포함한 표기
- 최소잔여·요약 박스·선택 합계는 **표시 기간 전체 기준**으로 계산
- 인접하지 않은 달(7월·9월)만 등록됐으면 이어보기를 막고 안내한다 — 8월 없이 이으면 중간이 빈 표가 된다

### 부수 효과 — 대기 전환 점검

지금은 다른 달 팀이면 판정을 포기한다.

```js
else if(!day || dep.slice(0,7)!==blkParsed.month){ verdict='타월/날짜확인'; }
```

여러 달이 등록돼 있으면 그 달 데이터로 판정할 수 있다. `blkUsedOn`으로 바꾸면 자동으로 따라온다.

## 5. 구현 결과

3단계 모두 적용했다. 확정 사항: **이어보기는 인접 2개월**, 등록월 보관 **3개월**, 미등록 구간은 **손님 공지에서 제외**(직원 화면에만 「판단 보류」).

### 날짜 키로 전환
`days` 항목에 `ymd`를 부여하고, 사용량 맵·오버부킹 보정 키를 일자(DD)에서 **날짜(YYYY-MM-DD)**로 바꿨다. 이어보기에서 7/15와 8/15가 같은 칸으로 취급되던 문제가 사라진다. 기존 오버부킹 값은 마지막 작업 월 기준으로 옮기고, 월을 알 수 없으면 버린다(개인 임시 시뮬레이션이라 손실이 작다).

### 월 경계 연박
`blkUsedOn(pool, ymd)` · `blkSpanRemain(pool, y, m, d, nights)` 신설. 연박 구간을 하루씩 날짜로 돌므로 달 경계가 없다.

- 다음 달이 등록돼 있으면 **정상 계산**
- 미등록이면 `{spill:'YYYY-MM'}` — 출발 일정 조회에 「판단 보류」로 **드러낸다**
- 손님 공지 PNG는 보류 건을 **넣지 않는다**(확인되지 않은 일정을 안내하지 않기 위함)

### 사용이 0인 달도 등록할 수 있게
파서는 사용>0인 칸만 행으로 만든다. 그래서 예약이 아직 없는 달은 행이 0개가 되고, 예전에는 「표 인식 실패」로 처리돼 **등록 자체가 불가능**했다. 그러면 월 경계 연박이 영원히 보류된다.

「표 형식을 못 알아봄(null)」과 「알아봤는데 사용이 0(빈 배열)」을 구분해, 후자는 정상 상태로 취급한다.

### 등록월 영속화
`mt_notify_blkMonths`에 저장. 로드 시 3개월 지난 달은 자동 정리.

### 이어보기
등록월 네비에 「표시 기간」 토글. 다음 달이 등록돼 있을 때만 활성. 표 열이 62칸이 되고 월 경계에 굵은 구분선과 `8/1` 표기가 붙는다. 요약·최소잔여·선택 합계는 표시 기간 전체 기준.

### 대기 전환
`dep.slice(0,7)!==blkParsed.month`로 다른 달을 포기하던 것을 `blkUsedOn`으로 바꿨다. 등록된 달이면 다른 달 팀도 판정한다.

## 6. 검증

`npm run verify` + Chromium **141개 통과**(페이지 에러 0)

이어보기 스위트(21)에 담은 것:

- 8월 미등록 시 7/29 수7박·7/30 목3박이 **정상 목록에서 빠지고 「판단 보류」에 뜨는지**
- 월 경계를 넘지 않는 7/23 목3박은 그대로 정상 목록인지 (회귀)
- 8월 등록 후 두 건이 **정상 목록으로 복귀**하는지
- 공지 PNG가 미등록일 때 빼고 등록 시 넣는지
- 사용 0인 달도 인식·등록되는지
- 이어보기 62칸·월 경계 구분선·`8/1` 표기·부제목
- 오버부킹이 7/15에만 적용되고 8/15에는 영향 없는지
- 새로고침 후 등록월이 유지되는지
