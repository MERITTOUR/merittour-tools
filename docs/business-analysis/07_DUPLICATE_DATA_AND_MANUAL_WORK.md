# 07 · 중복 데이터 · 수기 작업 (Duplicate Data & Manual Work)

> ✅ 코드 확정 / 🔎 추정 / ⚠ 확인 필요.

## A. 두 시스템에서 중복 관리 가능성이 있는 데이터
> ⚠ SaiZen 미분석이므로 "중복 후보"로 표기. 실제 중복 여부는 담당 확인 필요.

| 데이터 | 메리트투어(코드 확정) | SaiZen(추정) | 위험 |
|---|---|---|---|
| **야마나미 예약 인원/팀** | M클릭 → `teams[]`(매번 재업로드) | 월별 등록 데이터 | 인원 불일치·이중 입력 |
| **객실/블록 재고** | ② 호텔 블록(보유·잔여·임의배정) | 현장 객실 재고 | 오버부킹·잔여 산정 상이 |
| **리조트 단가(체재비·송영·관리비)** | 리조트 마스터(localStorage) | 현장 요금 | 단가 기준 불일치 |
| **명단/여권/연락처** | 일행별예약 | 체크인 명부 | 개인정보 다중 보관 |
| **송영 정보(항공시각)** | 항공시각 4종 | 송영 배차표 | 시각 갱신 누락 |
| **회원 정보/등급** | `회원권구분`·안내문 등급표 | (미상) | 등급별 예약 규칙 상이 |

## B. 수기 입력·오버레이 항목 (메리트투어 내부) ✅
> 원본(M클릭)은 불변, 사용자가 덮어쓰는 오버레이만 localStorage에 개인 PC별 저장. **담당자 개인 지식이 코드가 아닌 오버레이에 쌓임 → 인수인계 리스크.**

| 오버레이 | 키(localStorage) | 사용자가 수기로 정하는 것 |
|---|---|---|
| 예약 수정 | `mt_edit_overrides` | 구분·호텔Y/N·명단Y/N·비고(팀·특이사항 재파싱) |
| 팀 배정 | `mt_notify_teamAssign` | 팀명(비고 자동인식 `teamAuto`보다 우선) |
| 요금 조정 | `mt_notify_vAdjust` | 엔화 기타·원화 기타·패키지가(1인) |
| 발권 완료 | `mt_notify_ticketDone` | 발권 완료 체크 |
| 보험 제외 | `mt_notify_insExclude` | 개인 단위 보험 제외 |
| 정산 조정 | `mt_settle_adjust` | 항공원가·보험료·현지단가·송영비 + 체재/송영/관리비 제외 |
| 정산 공제 | `mt_settle_ded` | 공제 항목(쿠폰·이용권·포인트·선납 등) |
| 확정서 호텔명 | `mt_doc_hotelName` | 확정서에 찍을 실제 호텔명 |
| 확정서 계좌 | `mt_doc_acct` | 입금계좌·문의전화 |

## C. 기타 수기 작업(코드 외 관행) ✅ / 🔎
- **마스터 배포**: 관리자 입력 → JSON 내보내기 → 직원 각자 불러오기(수동, 서버 자동동기화 미적용). ✅
- **환율 입력**: 월별 테이블에 **사람이** "출발 N달 전 하나은행 현찰 살 때" 기준으로 수동 입력(자동 로직 없음). 🔎 관행
- **엑셀 재업로드**: 원본 미저장 → 세션마다 재업로드·재분석. ✅
- **보험 매칭**: 보험 도구에서 매칭 후 결과를 정산에 **수동 반영**(자동 임포트 없음). 🔎

## D. 시사점 (인수인계)
- 개인 PC에 흩어진 오버레이·마스터 = 공유·백업의 공백. 서버 정본화 시 우선 이전 대상: 리조트 마스터 → 팀배정/정산조정 → 명단(개인정보 권한 동반).
- SaiZen와의 이중 입력 지점(예약 인원·객실 재고·송영)이 통합 후보(06).
