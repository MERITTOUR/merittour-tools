# 06 · 야마나미(SaiZen) 연결 지점 (Integration Points)

> ⚠ **SaiZen(야마나미 운영관리 시스템) 소스는 이 저장소에 없어 미분석.** 아래는 **메리트투어 코드에서 확정된 데이터**(✅)를 기준으로 도출한 "SaiZen로 전달 가능한 후보"이며, SaiZen 쪽 수용 스키마·연결 방식은 **담당 확인 필요(⚠)**.

## 배경
- 메리트투어(한국 본사) = 예약·발권·정산 원천(M클릭 기반). SaiZen(일본 현장) = 야마나미 리조트 운영관리(월별 등록 데이터·객실·송영·현장). 두 시스템이 **같은 야마나미 예약**을 서로 다른 각도에서 다룸.
- 야마나미 권역 판별: `parseProduct`의 `accom` ∈ {야마나미(골프텔/관내별장/돔하우스), 쿠주힐즈, 간지호텔, 시즈노야도} (✅ 코드 내장). → 전체 예약에서 야마나미 권역만 필터해 전달 가능.

## 전달 가능한 핵심 데이터 (메리트투어 → SaiZen)
| 데이터 | 메리트투어 소스(✅) | SaiZen 활용 후보(⚠) |
|---|---|---|
| **행사(팀) 단위 예약** | `teams[]`: `eventSeq`·`eventNo`·`출발일/도착일`·`인원(pax)`·`상품명`·`숙소/룸타입`·`상태` | 월별 등록 데이터(N팀·N명), 객실 배정 |
| **명단(개인)** | 일행별예약: `고객명`·`영문성/이름`·`생년월일`·`성별`·`휴대번호`·`여권번호/만료일/발행국가` | 현장 체크인·투숙자 명부 |
| **항공 시각 4종** | `한국출발·현지도착·현지출발·한국도착` + `출발편/귀국편` | **송영 배차**(현지도착=출국 송영, 현지출발=귀국 송영) |
| **PNR/항공사/사전좌석** | buildApisMap | 항공 연동·좌석 |
| **숙소/룸 배정** | `parseProduct.accom/roomType` + `docHotelName`(실제 호텔명) | 객실 배정·재고 대사 |
| **호텔 블록 재고** | ② 호텔 블록(보유·별칭·임의배정·잔여) | SaiZen 재고와 대사(야마나미 capacity) |
| **확정서/일정표** | 확정서 JPG + (선택)서명 링크 | 현장 공유 |
| **결합 키** | `eventSeq`(내부)·`행사번호`(표시) | 양 시스템 매칭 키 후보 |

## 연결 방식
> ⚠ **구체적 연결 방식·스키마 설계는 본 분석의 범위 밖(설계 단계 과제)입니다.** 본 문서는 "무엇을 연결할 수 있는가"(위 데이터)만 다룹니다.
> 코드로 확인된 사실만: 대시보드에 확정·정산 팀을 `reservations` 테이블로 보내는 코드(`docSyncSupabase`)가 이미 존재하나 **연동설정 PC에서만 동작**하며, 그 테이블은 자동발송용 최소 컬럼이라 명단·여권·항공시각·숙소는 포함하지 않습니다(05 참조). 실제 연결·스키마·공유 키·개인정보 권한은 **SaiZen 담당과 별도 설계 단계에서** 확정.

## 주의
- 명단·여권·연락처는 **개인정보** → 전달 시 접근권한·최소화·마스킹 동반 필요(현재 메리트투어 측 RLS는 anon 개방, 보안 하드닝은 미머지 상태).
- 실제 "무엇을 SaiZen가 이미 보유/필요로 하는지"는 SaiZen 코드·담당 확인 후 확정(08 질문).
