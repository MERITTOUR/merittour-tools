# 홈페이지 예약 방법 안내 — 원본 (손님 사이트 `/2027/booking/`)

메리트투어 예약 홈페이지(www.merittour.co.kr · 엠클릭)에서 **로그인 → 출발지·호텔·기간·출발월 → 출발일·인원 → 약관 동의 → 예약 완료**까지를
실제 화면 캡처에 「누를 곳」 빨간 테두리를 얹어 안내하는 손님 페이지의 **조립 원본**이다. 완성 페이지는 손님 사이트 저장소
`merittour.github.io` 의 `2027/booking/index.html`(단일 HTML · 캡처 WebP 내장 · 약 570KB) — **그 파일은 손으로 고치지 않고 여기서 다시 조립해 통째로 바꾼다.**

처음 만든 곳: claude.ai 프로젝트 「Merittour 운영 관리 시스템」(2026-10-07 ~ 10-08 · Min 지시). 2026-10-08 zip 인수인계로 받아 두 저장소에 넣었다.

## 파일

```
build_guide.py        조립 스크립트 (Pillow 필요) — 단계 · 문구 · 자르기(crop) · 누를 곳(hl) 좌표의 단일 출처
guide.template.html   페이지 틀 (CSS · 히어로 · 휴대폰/PC 고르기 · 예약 순서 상자 · 문의 · 떠 있는 버튼 · 크게 보기)
logo.svg              /2027/ 의 .brand 로고 SVG 그대로
shots/*.png           페이지에 쓴 화면 캡처 21장 — 휴대폰 12장(01~16) + PC 9장(p01~p10) · 보정·가상 값 처리가 끝난 것만
patch/*.py            캡처 보정에 쓴 스크립트(참고용 · 원본 캡처가 없고 실제 값 자리는 <실제 …> 자리표시라 그대로는 돌지 않는다)
```

## 다시 만들기

```
cd site-src/booking-guide
python3 build_guide.py ../../../merittour.github.io/2027/booking/index.html
```

- 문구·단계·좌표는 `build_guide.py` 의 `MOBILE`(휴대폰) · `PC` 두 목록만 고친다. 좌표는 **원본 캡처 픽셀 기준**이고 조립할 때 % 로 바뀐다.
- 양쪽에 똑같이 들어가는 문구(로그인 방법 상자 `CRED` · 1인실 추가요금 `SINGLE` · 2인실 짝수 `ROOMS` · 예약금 `AFTER` · 로고 안내 `HOME_*`)는 파일 위쪽 상수 한 곳에만 있다 — **한쪽만 고쳐서 두 안내가 어긋나지 않게.**
- 새 캡처를 넣을 때: `shots/` 에 넣고 그 단계의 `img` · `crop` · `hl` 을 바꾼다. 휴대폰 캡처를 PC 안내에 임시로 쓰는 단계는 `phone=True` · `cap=PHONE_CAP`(PC 캡처가 생기면 둘 다 지운다).
- 조립 뒤 손님 사이트 저장소에서 검사(`booking-guide.mjs` · 390·800·1280px · `?view=` · 가로 넘침 · 이미지 로드 · 단계 수 · 전환 · 크게 보기)를 돌리고,
  손님이 다시 읽어야 하는 변경이면 `assets/fresh.json` 의 `/2027/booking/` 값을 올린다.

## 캡처의 개인정보 (공개 저장소)

- `shots/` 의 캡처는 **전부 가상 값**이다 — 홍길동 · hong@example.com · 010-1234-5678 · 예약번호 30001234. 실제 계정의 이름·이메일·휴대폰·예약번호가 보이는
  **원본 캡처는 어느 저장소에도 올리지 않는다.** 새로 캡처하면 올리기 전에 같은 가상 값으로 바꾼다(`patch/` 가 그 방법 — 글자는 화면과 같은 Noto Sans KR 로 다시 그린다).
- 캡처에 손댄 곳(실제 화면과 다를 수 있는 부분 · Min 결정): 「골프텔」→「호텔」(05 · 08 — 오픈 전에 실제 명칭도 바꿀 예정) · 여행기간 창에 「8일」 그려 넣음(06) ·
  출발월 창 제목 「언제 출발하시나요?」 + 2027년 3~12월(07 · p06) · 확인 창 기간 8일 · 출발월 2027년 3월(08). PC 캡처(p01~p07)에는 호텔 표기·8일 버튼이 이미 실제 화면에 있다.

## 페이지 구성

- 한 페이지에 「휴대폰 화면」(13단계)과 「PC 화면」(12단계 — 메뉴 버튼 없이 바로 로그인이라 한 단계 적다 · 그 밖 순서는 같다). `<html data-view="m|p">` 하나로 갈리고
  `?view=pc` · `?view=m` 이 먼저, 없으면 화면 폭 900px 기준. 히어로의 버튼으로 바꾸면 `history.replaceState` 로 주소에 남는다 → 손님에게 PC용 링크(`…/?view=pc`)를 따로 보낼 수 있다.
- 요소 id = 모드 앞머리 + 이름(`m-s-login` · `p-step-9` · `m-tip-home`). 큰 묶음 4개(로그인 · 조건 고르기 · 출발일·인원 · 약관 동의) + 참고 카드(로고 → 홈) 1개씩.
- 디자인 토큰·컴포넌트는 `/2027/` 과 같다(베이지 라이트 고정). 떠 있는 버튼 묶음의 「2027 안내 | 예약 방법」 오가기(`.fab-switch`)는 `/2027/` 에도 같은 자리에 있다 — 칸 순서·자리를 같게 둔다.
- 2026-10-08 Min 결정 기록은 손님 사이트 저장소 `CLAUDE.md` 「홈페이지 예약 방법 안내」 절에 있다(1인실 추가요금 문구에 호텔 이름 · 2인실 짝수 · 로고 안내 등 — 빼지 말 것).
